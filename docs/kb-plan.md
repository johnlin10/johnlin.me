# 知識庫規劃

把 Obsidian 的筆記放上網站，平常只有自己看得到，需要時開一條連結分享一篇或一個資料夾。第一個用途是交課堂筆記給老師。2026-09-22 定案，2026-09-23 重新設計分享範圍和網址（第五、六節）。做完一個階段就回來更新這份。

---

## 一、已經定下來的事

| 項目 | 決定 |
|---|---|
| 在哪裡寫 | 還是在 Obsidian 寫，網站不做編輯器 |
| 怎麼放上來 | `tools.johnlin.me/kb` 選頂層資料夾整包上傳，要更新就再傳一次 |
| 放哪些 | `KB_ROOTS`（`app/lib/kb.ts`）列出的頂層資料夾，目前只有 `學校/`。以後要放 `個人/` 就在這裡加一個名字。日記這類沒有理由上傳的就不要列進去 |
| 語法 | 一般 Markdown、表格、數學式、`[[連結]]`。callout、嵌入整篇、Dataview 都不做 |
| 圖片 | 先不做，筆記裡幾乎沒有圖 |
| 分享範圍 | 分享的筆記或資料夾，加上順著連結、只經過「知識資料夾」能連到的筆記（第五節） |
| 網址 | `johnlin.me/kb/{token}/行銷管理/行銷的定義`，路徑從分享範圍算起，不露出 vault 的完整路徑（第六節） |
| 分享頁 | 不帶網站的 Header 和 Footer，`noIndex`、`no-referrer`，跟完善就學的公開頁一樣 |
| 連結期限 | 一律不過期，不要了就撤銷（刪掉那一列） |
| 懸停預覽 | 滑鼠停在連結上就跳出那一篇的預覽；手機沒有懸停，點了直接跳頁 |
| 權限 | 三張表 RLS 只給 `is_admin()`；訪客只能走 `get_kb_share`、`get_kb_note` 兩支 security definer 函式，它們只回分享路徑 |

## 二、整體架構

分四層，每層只管一件事。規則要改，只動那一層。

| 層 | 決定什麼 | 在哪裡 |
|---|---|---|
| 上傳 | 哪些資料夾能上傳、怎麼同步 | `KB_ROOTS`、`KbTool.tsx`、`kb_sync` |
| 鏡像 | 存筆記 | `kb_notes` |
| 分享規則 | 看得到哪些筆記、訪客看到的路徑 | `kb_knowledge_folders`、`kb_share_paths`、`kb_share_view` |
| 畫面 | 把拿到的東西畫出來 | `app/[locale]/kb/[token]/` |

**訪客能知道的一切，都由資料庫的分享函式決定，網頁拿到什麼就畫什麼。** 分享函式是公開的，拿到 token 的人可以不經過網頁、直接呼叫 Supabase。所以範圍和路徑的轉換都要在資料庫裡做完，完整路徑不會離開資料庫。

## 三、上傳

**永遠整包上傳一個頂層資料夾，網站上的內容就是它的鏡像。** 瀏覽器選資料夾時只知道選的那一層以下的路徑，如果改成上傳子資料夾，就得另外問「這包要放到哪」，也要決定「替換」替換到哪一層。整包上傳就沒有這些問題。

1. 選 `KB_ROOTS` 裡的一個資料夾（`<input webkitdirectory>`）。選錯資料夾會被擋下來。
2. 只收 `.md`，跳過隱藏資料夾（`.claude/`）和 `CLAUDE.md`、`AGENTS.md`。路徑統一成 NFC。
3. 瀏覽器算每篇的 sha-256，跟資料庫比對，只送出新增和改過的。
4. 資料庫裡有、這次沒上傳的就刪掉。有要刪的時候，確認視窗會列出名字。
5. 寫入和刪除在 `kb_sync` 裡一個交易完成。空的上傳會被拒絕，免得誤操作把整個頂層資料夾刪光。

每個頂層資料夾各自同步：傳 `學校/` 只會新增、刪除 `學校/` 底下的筆記，不會動到其他資料夾。

路徑存成相對 vault 根目錄的形式（`學校/115-1/行銷管理/行銷的定義.md`），以後多收其他資料夾，舊資料的路徑不用改。

iPhone 的 Safari 不支援選資料夾，上傳只能在電腦上做。

## 四、資料表

```sql
kb_notes             (path text primary key, content text, hash text, links text[], updated_at)
kb_shares            (token text primary key, scope text, label text, created_at)
kb_knowledge_folders (path text primary key)
```

- **筆記的資料夾不另外存。** 資料夾從路徑推出來，上傳時也不用管資料夾的增刪。
- **`links` 在上傳時解析好存起來**（`extractLinks`），只存目標名稱，不存對到哪篇。解析結果只跟這篇的內容有關，所以只上傳改過的筆記也不會出錯。
- **連結對到哪篇，在資料庫裡現場查**（`kb_resolve`）：`[[名稱]]` 比對檔名，`[[資料夾/名稱]]` 比對路徑結尾，同名就選路徑最短的，跟 Obsidian 一樣。vault 的規則本來就不讓檔名重複，所以同名只是保險。
- **`scope`** 是筆記路徑（`.md` 結尾）或資料夾（`/` 結尾）。
- **`kb_knowledge_folders`** 一個資料夾一列，`/` 結尾，先放 `學校/資料庫/`。用途見第五節。
- **改名或搬資料夾**等於刪掉舊的、新增一篇新的，指到舊路徑的分享連結會失效。分享管理頁要標出這種連結。

## 五、分享範圍

**看得到的 = 分享範圍內的筆記，加上從它們出發、只經過知識資料夾能連到的所有筆記。**

知識資料夾放的是通用知識，例如 `學校/資料庫/`：

| | 在知識資料夾裡 | 不在知識資料夾裡（例：`學校/115-1/`） |
|---|---|---|
| 分享範圍內 | 看得到 | 看得到 |
| 範圍外，但連結連得到 | 看得到，裡面的連結也能繼續點 | 看不到，連結只顯示成文字 |
| 沒有分享連得到 | 看不到 | 看不到 |

**為什麼看資料夾、不看層數。** 以 2026-09-23 的 18 篇、分享「顧客價值、滿意度與忠誠度」來算：

- **只往外一層**（舊規則）：看得到它連到的 5 個概念，但這 5 個概念再連出去的 4P、4C、行銷、交換、顧客關係、Gary Armstrong 都變成文字，讀到一半就斷了。
- **不限層數**：概念底下的「來源」會連回課堂筆記。Philip Kotler 連回「行銷的定義」，第二層就把還沒交的課堂筆記帶出去了。限制在固定 N 層，也一樣會斷在第 N+1 層。
- **看資料夾**：16 個概念全部看得到、互相點得到，另一篇課堂筆記不會出現。

這條規則也管到其他頂層資料夾：沒列成知識資料夾的，一律不會被連結帶出去。以後放 `個人/`，預設不會外流；`個人/概念/` 想讓連結帶得到，就加一列。

**知識資料夾不等於公開。** 沒有分享連結的人什麼都看不到，它只決定拿到連結的人能順著連結看多遠。但只要有一條分享連得過去，裡面的筆記就看得到，所以私人內容不要放在知識資料夾裡。

已知、也接受的結果：

- 目錄會列出一路連得到的所有概念，資料庫越大越長。都是通用知識，沒關係。
- 課堂筆記連到範圍外的課堂筆記，會顯示成文字。同一科通常直接分享整個資料夾，不同資料夾的會分開分享。

函式：

- `kb_share_paths(token)`：看得到的筆記，照上面的規則沿著連結一路找。不開放給訪客。
- `kb_share_view(token)`：看得到的筆記和它們的分享路徑（第六節）。不開放給訪客。
- `get_kb_share(token)`：範圍和看得到的筆記清單（不含內容），路徑都是分享路徑。
- `get_kb_note(token, 分享路徑)`：一篇的內容，加上 `links`（目標名稱 → 分享路徑），只包含看得到的。不在 `links` 裡的連結，頁面就顯示成一般文字，連名稱都不會對到別的筆記。看不到的筆記回 null。
- 範圍在打開時現場算，重新上傳後多連的概念，老師那邊也會跟著出現。
- 分享頁每次都現場讀，不走快取：流量很小，而且撤銷之後必須立刻失效。`next build` 的路由表上要是 ƒ。

## 六、分享路徑

訪客看到的路徑（網址、目錄、原始碼）都是分享路徑，不是 vault 裡的完整路徑。

> **起點** = 分享範圍所在資料夾的上一層。分享一篇筆記時，是它所在資料夾的上一層。
> **分享路徑** = 完整路徑拿掉它跟起點共同的上層資料夾。資料庫回的保留 `.md`，網址上才去掉。

| 分享什麼 | 起點 | 看到的路徑 |
|---|---|---|
| 筆記 `學校/115-1/行銷管理/行銷的定義` | `學校/115-1/` | `行銷管理/行銷的定義`<br>`資料庫/行銷管理/核心概念/顧客價值` |
| 資料夾 `學校/115-1/行銷管理/` | `學校/115-1/` | `行銷管理/…`<br>`資料庫/行銷管理/…` |
| 筆記 `學校/資料庫/行銷管理/核心概念/顧客價值` | `學校/資料庫/行銷管理/` | `核心概念/顧客價值`<br>`框架/行銷組合（4P）`、`人物/Philip Kotler` |
| 筆記 `個人/閱讀/書A` | `個人/` | `閱讀/書A`<br>連到知識資料夾 `個人/概念/` 的是 `概念/…` |

- 規則裡沒有寫死任何資料夾名稱，放哪個頂層資料夾都是同一套。
- 分享路徑只跟分享範圍有關，重新上傳不會讓同一篇的網址變掉，除非改名、搬家或撞名。
- **撞名**：兩篇轉出來的分享路徑一樣時（例如 `學校/115-1/` 底下剛好也有一個「資料庫」資料夾），這條分享的所有路徑改用完整路徑（去掉 `.md`），確保每篇都點得到。
- 轉換在 `kb_share_view` 裡做，原因見第二節。

## 七、分享頁（`app/[locale]/kb/[token]/[[...path]]/`）

- **網址**：`/kb/{token}/行銷管理/行銷的定義`。沒帶路徑就打開分享的那篇，資料夾分享則打開樹上第一篇。proxy 的 matcher 會跳過含「.」的路徑，替 `/kb/` 加一條例外，檔名帶點（「1.2 定義」）也拿得到語系。
- **渲染**：react-markdown 加 remark-gfm、remark-math、rehype-katex，都是已經裝好的。`[[連結]]` 不寫 plugin，渲染前用 `linkify()` 換成一般的 Markdown 連結，對不到的直接換成文字。表格裡的 `[[a\|b]]` 換完就沒有 `|` 了，不會弄斷表格。
- **換行**：vault 沒開嚴格換行，Obsidian 的單一換行就是換行。段落和清單加 `white-space: pre-line`，不用裝 remark-breaks。
- **字型**：排版沿用文章內文（`PostContent.module.scss`），但內文改無襯線。源起明體只自架了一個字重又關掉假粗，筆記裡的粗體會跟內文一樣粗。標題照樣是襯線。
- **標題**：用檔名；內文第一行是同名的 `# 標題` 就拿掉，不顯示兩次。frontmatter 不顯示。
- **目錄**：看得到的筆記照分享路徑排成樹，跟網址一樣。React 的 `key` 也用分享路徑，原始碼裡看不到完整路徑。桌機在左邊黏著，高度撐滿整個視窗，捲動區上下用 `edge-fade-mask` 照站上的淡出曲線融進底色，不會在半空中被切掉。主題切換鈕（`ThemeToggle`）固定在目錄底部，不跟著捲。手機抽屜也一樣；抽屜的標題列放在捲動區外面，捲動區上下都淡出，桌機的標題則在捲動區裡。900px 以下改成從左邊滑出的抽屜，右下角的「目錄」按鈕打開。抽屜用原生 popover（點外面、按 Esc 收起，不用 JS），`key` 跟著筆記換，換頁就收起。收起時是 `display:none`，不留 iOS Safari 的常駐色帶；按鈕不貼底也是同一個原因。列印時只印內文。
- **懸停預覽**（`KbPreviewLink.tsx`）：滑鼠停在內文的筆記連結上 0.35 秒，旁邊跳出那一篇，下面空間不夠就放上面。滑鼠移進預覽不會收起，裡面的連結也能點；移開、按 Esc 或捲動頁面就收起。資料用 `get_kb_note` 從瀏覽器直接讀，同一篇只讀一次。觸控沒有懸停，點了直接跳頁。Markdown 和數學式的程式第一次懸停才載入，內文和預覽共用 `KbMarkdown.tsx`。預覽裡的連結不會再跳預覽。
- 沒有個人網站的 Header 和 Footer，`noIndex`、`referrer: no-referrer`。token 不對或筆記在範圍外都是 404，404 頁不帶這頁的標題。

## 九、這次不做

- **圖片。** 要做的話走 R2，已知代價是撤銷分享後，拿過圖片網址的人還是打得開。
- **進階語法**：callout、嵌入整篇、Dataview。
- **改名時自動修連結。** Obsidian 會自己改好，上傳的是改好之後的內容，所以只有網站這邊的分享連結會受影響。
- **標題錨點**：`[[筆記#標題]]` 只連到那一篇，不會跳到那個標題。
- **超過 1000 篇**：PostgREST 一次最多回 1000 列，到那時候再改成分頁。
- **先算好範圍**：每次打開分享頁，都要沿著連結一路找、現場對連結。現在幾十篇沒差，等筆記多到分享頁變慢，再改成先算好存起來。
